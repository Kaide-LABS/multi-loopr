multi-loopr

Two independent AI coding assistants build the same piece of software, under one plan, with one checking the other's work as a genuinely separate reader.

Before either assistant writes a line of code, the plan goes through loopr, the spec-discipline layer this tool runs: an interrogation against a six-part stopping test — does the plan name a real outcome, is it independently checkable, are its edges named, is its boundary confirmed, is there real context worth keeping, are there no unresolved unknowns. A human confirms the resulting spec before anything is built. Once building starts, multi-loopr hands each phase between two independent providers: one implements, the other reviews. The reviewer defaults to whichever provider did not write the diff under review, so the check is a second, separate read of the work — not the same model re-reading its own reasoning. An operator can pin either provider to a fixed role; if a pinning would force a provider to review its own prior work, multi-loopr surfaces that plainly rather than letting it pass unnoticed.

What it does today

multi-loopr run

Dispatches one phase's turn sequence between the two configured providers, and mechanically checks that every turn genuinely references the phase's own spec and prior handoff record.

multi-loopr drive

Walks a build through every phase of a target project unattended: after each phase, it decides — from the real state on disk — whether to dispatch the next phase, stop cleanly, or halt on an incoherent state, and logs every decision.

Role pinning

Pin either provider exclusively to the executor role or exclusively to the reviewer role, instead of the default alternation. An impossible pinning is rejected before any turn runs; a pinning that would force self-review is surfaced as a warning, never silently allowed.

multi-loopr evidence

Independently re-derives whether a completed run actually met its own completion criteria, from the run's persisted handoff records, offline — without trusting what the run reported live.

multi-loopr mcp

Exposes run, drive, doctor, and evidence as Model Context Protocol tools over stdio, so any MCP-capable client can drive a build conversationally without hand-writing a config file.

multi-loopr setup

Registers multi-loopr's own MCP server plus two optional research servers (arXiv, paper-search) in one command. Both are optional — nothing about multi-loopr requires them.

The provider set today is exactly two: Claude Code and Codex CLI.

How to try it

multi-loopr is MIT-licensed and published on npm. It runs entirely on your own machine, using your own Claude Code and Codex CLI credentials — there is no hosted account and no service multi-loopr operates on your behalf. 

npm install -g multi-loopr
multi-loopr doctor

doctor checks your toolchain and both provider CLIs before you run anything. Full usage is in the README.
